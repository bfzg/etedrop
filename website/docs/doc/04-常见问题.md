# FAQ

:::info

The question titles below are extracted from the "FAQ" section on the homepage for unified maintenance in docs.  
You can directly expand or rewrite each detailed answer under **A:**.

:::

## 1. Does it rely on centralized storage?

**A:** Core transfer is end-to-end direct connection whenever possible; the server mainly handles online management and signaling.

---

## 2. Can it work on public networks?

**A:** Yes. About 80% of user network environments support P2P transfer. If yours does not, please send us a screenshot.

---

## 3. Which file types support online preview?

**A:** On the receiver's **web share page**, the following types can be previewed online (no client installation required):

- **Video**: standard **MP4** (supports streaming while receiving, depending on browser and codec).
- **Images**: such as JPG, PNG, GIF, BMP, WebP, ICO, SVG, etc.
- **PDF**: can be opened in a **new tab** after receiving finishes.
- **Audio**: such as MP3, WAV, OGG, M4A, AAC, FLAC, OPUS, etc., played with the built-in player.
- **Text and code**: such as TXT, Markdown, LOG, JSON/XML/YAML, CSV, and common source-code extensions. Very large files may not render fully inline; download first if needed (the app has a preview size limit for text).

**Not supported for online preview** (please download and open with local software): Word/Excel/PPT, archives, installers, etc.

---

## 4. What if preview is unavailable or video playback fails?

**A:**

- **Video**: must be browser-decodable **MP4**. If codec is not supported, download and play locally. Some environments (for example desktop Safari) may limit inline video preview; try Chrome first or download to view.
- **Opened inside WeChat**: due to embedded browser capability limits, **video preview** may require features like **MSE**. If preview fails, open the same link in a system browser (such as Chrome).
- **Image / PDF**: wait until receiving progress completes, then open in a **new tab** as prompted.
- If issues persist, please send a **screenshot** with device model, browser, and filename to **yuanzhou_cn@qq.com**.

---

## 5. How do I report an issue?

**A:** Please send screenshots and a brief issue description to yuanzhou_cn@qq.com.
