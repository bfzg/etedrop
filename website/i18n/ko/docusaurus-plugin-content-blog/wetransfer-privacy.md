WeTransfer는 클라우드 서버 업로드로 동작 — 프라이버시 공백은 거기서 시작합니다.

EteDrop — 직접 전송 설계 — 는 P2P: 발신 기기→수신 기기, 중간 서버 없음. 차이는 기능이 아니라 *아키텍처*입니다.

## 1. 제3자 서버 저장

WeTransfer 전송 시 AWS 등 인프라로 업로드. 무료는 최대 ~7일 보관 — 운영자가 조건하에 접근 가능.

EteDrop은 파일이 서버에 도달하지 않음; 완료 후 두 기기에만 존재.

## 2. 서버 측 암호화도 운영자는 복호화 가능

표준 관행이지만 키는 서비스 측 — 수신자에게 넘기려면 서버가 읽을 수 있어야 합니다. 클라우드 중계 구조의 특성.

P2P는 WebRTC DTLS end-to-end; 시그널링은 연결만 — 파일 내용 비접촉.

## 3. 링크만 — URL 아는 사람은 DL

비밀번호·2차 인증 없음 — 링크 유출·전달 위험.

EteDrop: 링크+픽업 코드 — 2요소.

## 4. 메타데이터 수집·보관

WeTransfer는 이메일, 파일명, 크기, IP, 타임스탬프 등 — 공유 활동 기록.

EteDrop은 NAT용 IP 등 연결 메타데이터만 일시 처리; 완료 후 파일 메타데이터 미보관.

## 5. 관할·법적 노출

EU·미 등 데이터 처리 — 법 집행·법원 명령 대상. 서버上的 데이터는 제공 요구 가능.

P2P는 본문이 그런 서버에 안 가서 노출 감소; 시그널링은 단명.

## P2P 대안

- **프라이버시:** 서버 미경유
- **속도:** 1구간; LAN 특히 빠름
- **경험:** DL 전 미리보기

P2P는 양쪽 온라인 — 비동기는 클라우드. 민감 파일엔 구조적 공백이 중요.

## WeTransfer가 여전히 맞는 경우

- 비동기 배달
- 브랜드 페이지, 팀 분석
- 픽업 코드에 익숙하지 않은 수신자
