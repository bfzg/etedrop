# 数据模型设计

## 一、背景与目标

Eddy 服务端当前所有状态均存于内存（无数据库），主要包括：**取件码会话**、**设备在线状态**、**分享记录**。本文档定义这三类模型的结构、索引与过期策略，便于实现一致性与后续持久化改造。

---

## 二、范围

| In Scope | Out of Scope |
|----------|--------------|
| devices、sessions、shares 的字段与含义 | 具体序列化格式（JSON/DB schema） |
| 唯一约束与 key 设计 | Flutter/Desktop 端本地存储模型 |
| 过期与清理策略 | 鉴权相关模型（如 token） |

---

## 三、模型定义

### 3.1 设备状态（devices）

**用途**：信令服务在 `/api/share` 上维护的「已上线设备」集合，用于设备注册、心跳与后续浏览器连接设备转发。

**存储**：`Map<string, DeviceState>`，key = `deviceId`。

| 字段 | 类型 | 说明 |
|------|------|------|
| deviceId | string | 设备唯一标识（如 UUID），与 key 一致 |
| deviceName | string | 设备名称（展示用） |
| lastSeenAt | number | 最后心跳/活动时间戳（毫秒） |
| ws | WebSocket | 该设备当前连接实例 |

**唯一约束**：同一 `deviceId` 仅允许一条连接；新连接上线会关闭同 deviceId 的旧连接。

**过期策略**：若 `Date.now() - lastSeenAt > DEVICE_INACTIVE_TIMEOUT_MS`（当前 120_000 ms），则删除该设备并关闭 ws。

---

### 3.2 取件码会话（sessions）

**用途**：`/api/connect` 上发送方与接收方的配对关系，以及 sdp/candidate 转发目标。

**存储**：`Map<string, SignalingSession>`，key = 取件码（6 位十六进制大写）。

| 字段 | 类型 | 说明 |
|------|------|------|
| code | string | 取件码，与 key 一致 |
| sender | WebSocket \| undefined | 发送方连接 |
| receiver | WebSocket \| undefined | 接收方连接 |
| createdAt | number | 会话创建时间戳（毫秒） |

**唯一约束**：一个取件码对应一个会话；同一取件码只允许一名接收方加入。

**过期策略**：若 `Date.now() - createdAt > SESSION_TIMEOUT_MS`（当前 10 * 60_000 ms），则向双方发送「会话已超时」并关闭连接、删除会话。

**辅助结构**：`Map<WebSocket, SocketSessionState>`，用于根据连接反查角色与取件码。`SocketSessionState` 含 `role: 'sender' | 'receiver'`、`code: string`。

---

### 3.3 分享记录（shares）

**用途**：分享记录存储。**仅存在于客户端本地**，服务端不存储任何分享数据。

- **存储位置**：Flutter/Desktop 端本地 `shares.json`（`ShareService` + `path_provider`），分享的创建、查询、删除均为纯本地操作。
- **服务端角色**：不参与分享记录的存储与管理，仅通过 WebSocket 信令建立 Desktop ↔ 浏览器的 P2P 连接。浏览器访问分享链接后，通过 P2P DataChannel 向 Desktop 请求分享信息。
- **服务端 ShareModule（待移除）**：当前服务端仍有 REST 分享 API（内存 Map），属于早期实现遗留，未被客户端调用，后续应移除以保持架构一致。

**客户端存储结构**（`shares.json`）：

| 字段 | 类型 | 说明 |
|------|------|------|
| code | string | 分享码（8 位十六进制大写） |
| path | string | 文件相对路径 |
| fileName | string | 文件名 |
| size | number | 文件大小（字节） |
| passwordHash | string \| undefined | 密码的 SHA256 哈希（hex）；无密码则无此字段 |
| createdAt | number | 创建时间戳（毫秒） |
| expiresAt | number \| undefined | 过期时间戳；无则永不过期 |

**唯一约束**：生成新码时保证不与现有 key 重复。

**过期策略**：查询与列表时，若 `expiresAt` 存在且 `Date.now() > expiresAt`，则删除该条并视为不存在；列表接口会在返回前先做一次过期清理。

---

## 四、索引与查询

| 模型 | 主键/索引 | 常用查询方式 |
|------|----------|--------------|
| devices | deviceId（Map key） | 按 deviceId 查设备、按 ws 反查 deviceId（另表 socketDeviceId） |
| sessions | code（Map key） | 按取件码查会话；按 ws 查角色与 code（socketSessions） |
| shares | code（Map key） | 按规范化 code 查记录；列表为全量遍历后按 createdAt 排序 |

当前无跨模型联合查询。浏览器「连接设备」时按 deviceId 查 devices，并通过 `browserToDevice`（`Map<WebSocket, deviceId>`）和 `deviceToBrowser`（`Map<deviceId, WebSocket>`）维护浏览器↔设备的配对关系，用于信令双向转发。

---

## 五、异常与边界处理

- **devices**：同一 deviceId 重复上线时，旧连接被关闭并从 Map 中替换为新连接。
- **sessions**：发送方或接收方断开时，对端收到 err 并清理该端引用；若双方皆空则删除会话。
- **shares**：code 查询前统一 `trim().toUpperCase()`；删除时同样规范化，避免 key 不一致。

## 七、待办项与风险

| 待办 | 说明 |
|------|------|
| 持久化 | 若需重启不丢失，需将 devices/sessions 之一或全部落库或 Redis，并定义迁移方案 |
| 多实例 | 当前为单进程内存，多实例部署时 sessions/devices 需共享或粘性路由 |
| 移除服务端 ShareModule | 分享数据只存客户端本地，服务端 REST 分享 API 属于遗留代码，应移除以保持架构清晰 |

**风险**：超时常量（如 2 分钟设备、10 分钟会话）写死在代码中，变更时需同步文档与配置化考虑。
