# Ubuntu 部署配置（Nginx + HTTPS + fast_send_server + 官网）

约定：**后端** `127.0.0.1:40321`，**静态站目录** `/home/app/www.etedrop.com`（仅为服务器路径名，与域名后缀无关），**Nginx 站点文件** `/etc/nginx/sites-enabled/api`。海外用 **`doc/nginx-etedrop.conf.example`**（本文不改动海外示例）。国内 **仅 `etedrop.cn`**（API：`api.etedrop.cn`；官网：`etedrop.cn` / `www.etedrop.cn` / `*.etedrop.cn`）用 **`doc/nginx-etedrop-cn.conf.example`**（勿整份照搬海外示例，避免引用 `etedrop.com` 等海外证书路径）。

---

## 1. DNS（Cloudflare 等）

### 海外（国际站，示例）

| 记录 | 类型 | 指向 |
|------|------|------|
| `api.etedrop.com` | A | 海外服务器公网 IP |
| `etedrop.com` / `www.etedrop.com` | A | 海外或按需 |

### 国内（独立域名 etedrop.cn）

| 记录 | 类型 | 指向 |
|------|------|------|
| `api.etedrop.cn` | A | **国内**服务器公网 IP（API） |
| `etedrop.cn` | A | **国内**服务器公网 IP（官网） |
| `www.etedrop.cn` | A | **国内**服务器公网 IP（官网） |
| `*.etedrop.cn` | A | **国内**服务器公网 IP（泛解析，与官网同源） |

> 旧版国内曾用 `cn.etedrop.com`、`api-cn.etedrop.com`；现以 **etedrop.cn / api.etedrop.cn** 为准（国内站不再使用 `etedrop.com` 主机名）。Nginx 与证书仅针对上述 `.cn` 记录。

证书申请期间：经 Cloudflare 解析的对应主机名设为 **DNS only（灰云）**。证书就绪后：**Proxied**，**SSL/TLS → Full (strict)**（按你实际策略调整）。

curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.4/install.sh | bash

## 3. 官网静态文件

```bash
sudo mkdir -p /home/app/www.etedrop.com
sudo chown -R www-data:www-data /home/app/www.etedrop.com
sudo chmod o+x /home /home/app
```

本机构建产物同步（路径按你 Docusaurus 输出改）：

```bash
rsync -av --delete ./website/build/ user@服务器:/home/app/www.etedrop.com/
```

**国内站**构建（默认中文根路径 + 备案等，见 `website` 目录说明）：

```bash
npm run build:domestic
```

海外主站构建产物若需带「国内镜像」文案里的地址，构建时可指定镜像根 URL（与当前国内官网一致即可），例如：

```bash
CHINA_MIRROR_ORIGIN=https://etedrop.cn npm run build
```

## 4. Nginx

```bash
sudo apt install -y nginx
sudo systemctl enable nginx
sudo systemctl start nginx
sudo rm -f /etc/nginx/sites-enabled/default
sudo rm -f /etc/nginx/sites-enabled/api
```

海外机：

```bash
sudo cp /path/to/repo/doc/nginx-etedrop.conf.example /etc/nginx/sites-enabled/api
```

国内机（**api.etedrop.cn** + **etedrop.cn** 官网及泛域名）：

```bash
sudo cp /path/to/repo/doc/nginx-etedrop-cn.conf.example /etc/nginx/sites-enabled/api
```

```bash
sudo nano /etc/nginx/sites-enabled/api
sudo nginx -t && sudo systemctl reload nginx
```

直接编辑 **`/etc/nginx/sites-enabled/api`**（普通文件，非软链）。

`api` 内按需改：`root`、`ssl_certificate` / `ssl_certificate_key`；**`http {}` 里 `map $http_upgrade $connection_upgrade` 全局只保留一份**；证书未下发前注释掉对应 **`listen 443`** 整段 `server`。  
泛域名 **`*.etedrop.cn`** 的证书常见为 DNS 验证单独签发，路径可能与仅 `etedrop.cn` 不同，以 `certbot certificates` 为准。

## 5. Certbot

```bash
sudo apt install -y certbot python3-certbot-nginx
```

海外机（示例，与 **`nginx-etedrop.conf.example`** 一致）：

```bash
sudo certbot certonly --webroot -w /var/www/html -d etedrop.com -d www.etedrop.com
sudo certbot certonly --webroot -w /var/www/html -d api.etedrop.com
```

国内机（与 **`nginx-etedrop-cn.conf.example`** 一致；仅 `.cn` 主机名，泛域名按需 DNS-01）：

```bash
sudo certbot certonly --webroot -w /var/www/html -d api.etedrop.cn
sudo certbot certonly --webroot -w /var/www/html -d etedrop.cn -d www.etedrop.cn
# 泛域名 *.etedrop.cn 多为 DNS-01，示例：
# sudo certbot certonly --manual --preferred-challenges dns -d "*.etedrop.cn" -d etedrop.cn
```

```bash
sudo certbot certificates
systemctl list-timers | grep certbot
sudo certbot renew --dry-run
```

Nginx 里 `ssl_certificate` 等与 `certbot certificates` 一致；**国内**官网证书目录常见为 `/etc/letsencrypt/live/etedrop.cn/`，API 为 `/etc/letsencrypt/live/api.etedrop.cn/`；**勿照抄海外** `etedrop.com` / `api.etedrop.com` 路径到国内机。
