# 服务端架构总览

## 一、背景与目标

FastSend 服务端基于 NestJS，提供两类能力：**WebSocket 信令**（取件码传文件、设备注册/分享）与 **分享 REST API**（当前为服务端内存存储）。本文档描述分层结构、模块边界与依赖关系，便于新人上手与后续扩展。

---

## 二、范围

| In Scope | Out of Scope |
|----------|--------------|
| NestJS 模块划分、目录结构 | 前端/Flutter 实现 |
| 信令与分享模块的职责边界 | 具体 WebRTC/SDP 格式 |
| 内存状态（sessions、devices、shares） | 持久化方案（DB/Redis） |
| HTTP 与 WS 端点一览 | 鉴权、部署、监控 |

---

## 三、整体架构

```
┌──────────────────────────────────────────────────────────────────────────┐
│                              AppModule                                    │
│  ┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐          │
│  │ AppController   │  │ ShareModule     │  │ SignalingModule  │          │
│  │ GET /           │  │ ShareController│  │ SignalingController│         │
│  │ AppService      │  │ ShareService    │  │ SignalingService  │          │
│  └─────────────────┘  └────────┬────────┘  └────────┬─────────┘          │
│                                 │                    │                    │
│  ┌─────────────────┐  REST /api/share(遗留)    WS /api/connect           │
│  │SharePageModule  │            │              WS /api/share             │
│  │SharePageController│          │                    │                    │
│  │ GET /share/:id/:code│        │                    │                    │
│  │SharePageService  │          │                    │                    │
│  └─────────────────┘          │                    │                    │
└────────────────────────────────┼──────────────────┼──────────────────────┘
                                  │                  │
                       shares (Map, 遗留)   sessions (Map) + devices (Map)
                                             + browserToDevice / deviceToBrowser (Map)
```

- **入口**：`main.ts` 创建 Nest 应用，监听 `process.env.PORT ?? 3000`，启动时打印 HTTP 和 WebSocket 端点日志。
- **根模块**：`AppModule` 仅做组装，无业务逻辑；业务集中在 `ShareModule`、`SharePageModule` 与 `SignalingModule`。

## 四、模块与依赖

### 4.1 AppModule

| 职责 | 说明 |
|------|------|
| 组装 | 导入 `ShareModule`、`SignalingModule`，注册 `AppController`、`AppService` |
| 根路由 | `AppController` 提供 `GET /`，返回欢迎信息（可后续改为健康检查） |

**依赖**：无业务依赖，仅框架与子模块。

---

### 4.2 ShareModule（遗留，待移除）

> ⚠️ 分享记录只存客户端本地，服务端不应存储分享数据。此模块为早期实现遗留，当前未被任何客户端调用，后续应移除。

| 职责 | 说明 |
|------|------|
| ~~分享 CRUD~~ | 创建、列表、按码查询、删除分享记录（遗留） |
| ~~存储~~ | 进程内 `Map<string, ShareRecord>`，重启丢失（遗留） |

**边界**：

- **Controller**：`ShareController`，路由前缀 `api/share`。
- **Service**：`ShareService`，无对外依赖。

**依赖**：仅 Nest 与 Node 内置（crypto），不依赖 SignalingModule。

---

### 4.3 SignalingModule

| 职责 | 说明 |
|------|------|
| 取件码通道 | `/api/connect`：send/receive/code、sdp/candidate 转发，会话超时清理 |
| 分享/设备通道 | `/api/share`：device-online、心跳、设备超时踢下线；浏览器 connect + 设备在线检测 + offer/answer/ice 双向转发 |
| 运行时统计 | 在线设备数、等待中/已配对会话数（供健康接口使用） |

**边界**：

- **Controller**：`SignalingController`，仅提供 `GET api/system/health`，返回服务名与信令统计。
- **Service**：`SignalingService`，在 `onModuleInit` 中挂载两条 WebSocket 到 HTTP 同一 server（`attachWsUpgradeHandler`），路径来自 `signaling-paths.ts`。

**依赖**：

- `HttpAdapterHost`：获取底层 HTTP Server，用于 WS 升级。
- `common/interfaces/signaling-state.interface.ts`、`ws-message.interface.ts`。
- `signaling/constants/signaling-paths.ts`：路径与超时常量。

**不依赖**：ShareModule、SharePageModule（两条通道与分享 REST/分享页解耦）。

---

### 4.4 SharePageModule

| 职责 | 说明 |
|------|------|
| 分享页渲染 | 提供 `GET /share/:deviceId/:shareCode` 路由，返回通用分享下载页 HTML |
| 页面逻辑 | 页面通过 JS 连接 `/api/share` WebSocket，带上 deviceId 进行设备在线检测与 WebRTC 信令交换 |

**边界**：

- **Controller**：`SharePageController`，路由前缀 `share`。
- **Service**：`SharePageService`，负责 HTML 模板渲染。

**依赖**：无业务依赖，不依赖 ShareModule 或 SignalingModule。

## 六、异常与边界处理

- **分享**：code 查询时做 trim + 大写规范化；不存在或过期返回 404；密码错误不暴露，统一「不存在或已过期」。
- **信令**：非法 JSON 或缺少 `type` 回复 `err`；未注册设备发心跳回复 `err`；会话/对端不存在时回复 `err` 并清理状态。
- **超时**：取件码会话 10 分钟、设备无心跳 2 分钟，由 SignalingService 定时器清理。

---

## 七、验收标准

- 能说清 App / Share / Signaling 三大块职责，以及「分享 REST」与「两条 WS」之间无循环依赖。
- 新增开发者能按本文档找到对应模块与接口定义。
- 健康接口 `GET api/system/health` 返回信令统计（onlineDevices、waitingSessions、pairedSessions）。

## 八、待办项与风险

| 待办 | 说明 |
|------|------|
| ~~分享页路由~~ | ✅ 已实现：`SharePageModule` 提供 `GET /share/:deviceId/:shareCode` |
