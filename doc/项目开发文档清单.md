## 7. P1/P2 文档与服务端后续工作

### P1/P2 文档是否还需要

**需要，建议按节奏做。**

- **P1**（认证、可靠性、TURN/STUN、错误码规范、日志）：上线前或要做多用户/公网部署时很有用，可分批写；其中《错误码规范》可优先，把当前信令里已用的 code（如 OFFLINE、SESSION_TIMEOUT）整理成表，便于前后端统一。
- **P2**（测试、部署、发版清单、运维、路线图）：正式上线前必做，用于保证可测试、可部署、可运维。

若当前只做内测或 MVP，可先不写全，但建议至少保留清单，需要时再补。

### 服务端还有哪些工作（可选 / 后续）

| 类别 | 说明 | 对应文档 |
|------|------|----------|
| 鉴权 | 当前无 JWT/设备签名；若要做多租户或接口保护再加 | 认证与安全设计 |
| 持久化 | devices/shares/sessions 均内存，重启丢失；可后续加 DB/Redis | 数据模型设计、部署与环境配置 |
| TURN 配置 | 信令已有，WebRTC 穿透依赖客户端 ICE 配置；若自建 TURN 可加配置接口或凭证下发 | TURN与STUN策略 |
| 错误码文档化 | 信令已带 code，可整理成《错误码规范》供 Flutter/前端对齐 | 错误码规范 |
| 分享页业务扩展 | 当前分享页仅「连接设备 + 在线/离线」；文件信息、密码、下载等走 P2P，在 Flutter 或分享页 JS 里实现 | WebRTC网盘与分享方案 §8 |
| 单测/集成 | 为关键路径补测试，便于重构与发版 | 测试策略 |
| 部署与运维 | Docker、环境变量、监控、故障处理 | 部署与环境配置、运维手册 |

**小结**：核心信令与分享流程已闭环，P1/P2 文档和上表所列工作属于「增强与上线就绪」，可按业务节奏分批做，不必一次做完。
