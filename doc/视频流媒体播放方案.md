视频流媒体播放方案：DataChannel + MSE 增强

为什么不用 WebRTC 视频轨（RTP）推流

经过详细调研，WebRTC 视频轨方案不可行，原因如下：





flutter_webrtc 没有注入外部视频源的 API：该库只支持摄像头/屏幕采集（getUserMedia / getDisplayMedia），没有任何 Dart API 可以将 FFmpeg 的 H.264/H.265 码流注入为 MediaStreamTrack。要实现需要在 macOS/Windows 分别写 C++/ObjC 原生代码 fork 插件，工作量巨大且不可维护。



浏览器对 live MediaStream 不支持 VOD 特性：`<video srcObject={stream}>` 播放 WebRTC 实时流时，duration 为 Infinity，currentTime 不可随意设置（无法 seek），playbackRate 在多数引擎上被忽略或 clamp，进度条无法正常工作。这与你要求的"可拖动进度条 + 倍速"完全矛盾。



当前项目零基础：仓库中 WebRTC 仅用于 DataChannel，没有任何 video/audio track 的代码路径，从零搭建 RTP 推流链路不现实。

正确方案：修复并增强 DataChannel + MSE

现有的 init-segment-v1 协议和 MSE 架构概念上是正确的。之前遇到的 DEMUXER_ERROR 是实现 bug（codec 不匹配、box 解析边界问题、init 段错误包含 moof），不是架构缺陷。MSE 天然支持：





seek：通过 video.currentTime = X 在已缓冲区间内跳转；超出缓冲区间时走 DataChannel 信令让 desktop 重新定位



playbackRate：video.playbackRate = 2.0 对 MSE 原生有效，无需 desktop 配合



进度条：MSE 通过 duration 和 buffered 提供完整的 VOD 时间线

具体改动

1. 修复 MSE 播放 (P0 - 让播放跑通)

Desktop (share_p2p_handler.dart):





_onStreamStart 中用 ffprobe 获取视频 duration（秒），放入 stream-meta 发给 web



扩展 codec 检测：除 H.264 外，也允许 H.265（后续由 web 端 isTypeSupported 判断）



优化 _probeCodec 中的正则（当前 \\r?\\n 的双斜杠在 Dart 中实际是 \r?\n 字面量，可能导致解析异常）

Web (useSharePage.ts):





stream-meta 处理中：收到 duration 后设置 MediaSource.duration



pickSupportedMp4Mime：增加 H.265 候选 MIME（hev1.1.6.L93.B0 等），动态检测浏览器支持



增加详细错误日志：在 appendBuffer 失败时输出 box 类型和大小

Web (types.ts):





StreamMeta 增加 duration?: number、codecs?: string 字段

2. Seek 跳转 (P1)

协议新增消息:

```ts
// Web -> Desktop（秒）
{ type: "stream-seek", targetTime: number }

// Desktop -> Web（实际定位到的关键帧时间）
{ type: "stream-seeked", actualTime: number }
```

Desktop (share_p2p_handler.dart):





_handleDcMessage 增加 stream-seek case



实现 _onStreamSeek：kill 当前 FFmpeg 进程 -> 用 `-ss <targetTime>` 重启 FFmpeg -> 重发 init segment + 新 media segments



FFmpeg 命令中 -ss 放在 -i 前面（input seeking，快速定位到最近关键帧）

Web (useSharePage.ts):





监听 `<video>` 的 seeking 事件：如果目标时间超出 buffered 范围，发送 stream-seek



收到 stream-seeked 后：sourceBuffer.remove(0, Infinity) 清空旧数据，重置 init/segment 状态，准备接收新段



stream-meta 收到 seeked 标志时重置 MSE 状态（mseInitDoneRef 等）

Web (SharePageView.tsx):





在 `<video>` 上增加 onSeeking handler



hook 返回新方法 sendSeek(time: number)
